## Facts measured before the design choices
- HGQ2 variable shapes do not depend on the batch dim used at build: QDense/QEinsum/QSoftmax built with batch
  `None` and batch `2` give identical `(name, shape, dtype)` lists (jax probe). Datalane quantizers collapse axis 0,
  also for the batch-less Linformer projection input `(160, 256)` -> bits `(1, 256)`.
- Variable names repeat inside one HGQ2 layer (`i`, `k`, `f`, `beta`, `ebops`), so golden weights are matched per
  named leaf by position, with `(name, shape, dtype)` asserted.

## Deviations from the plan / hybrid
1. **Value residual API.** `Attention.call(..., initial_v=None)` returns `(out, v_cache)` when
   `value_residual=True` (first layer: its projected values; later layers: mix in `initial_v` and pass it on;
   `initial_v=None` means no mixing, as torch with `initial_values=None`), else `out`. `EncoderLayer.call` always
   returns `(x, initial_v)`. `Residual` forwards a tuple's second element. S3's decoder layers use plain
   attention (no value residual), so they get `out`.
2. **Norms.** Only `LayerNorm` and `CustomLayerNorm` (same op in fp32) are implemented. The other hepattn norms
   raise `NotImplementedError`, unknown names `ValueError`. CLIC uses LayerNorm only.
3. **Constructor inputs.** Activations are names (`silu`, `SiLU`, `torch.nn.SiLU`, `SwiGLU`); a non-string raises
   `TypeError`. `InputNet` takes `net` (Dense kwargs) and `posenc` (FourierPositionEncoder kwargs) dicts, not torch
   modules; `input_dtype` and other posenc classes raise. `drop_path > 0` raises (plan: needs SeedGenerator state).
4. **Porting.** The torch -> native porting helper is a test utility (`tests/keras_native/porting.py`), not a
   converter module. S7 owns the checkpoint converter and can reuse it.
5. **Golden layout.** One file per case with all its modes (`cases.modes`) (inputs and torch reference state are shared):
   9 files, 4.81 MB (27 single-mode files were 10.0 MB). Leaf variables are stored as
   `<mode>::kv::<leaf>::<idx>::<var name>`; `meta` also records each leaf variable's `trainable` flag per mode
   (added in the review fix). Native weights: torch reference state -> `porting.py`, then every leaf variable from
   the file, with name/shape/dtype asserted. Regenerating gives bit-identical arrays (2349 arrays + 9 meta
   compared, 0 differ; again after the meta change).
6. **Paired delta per layer, not per model.** The plan's "high ~0.30 vs low ~31" is the full-model layer-0 mask
   logit, which needs the S3 decoder and mask task. That reproduction is **deferred to S3**. In S2 the criterion
   (low/high >= 10x) is applied to each golden case: 7 of 9 pass with ratios 28-308. A single Linformer layer
   separates only 5.3x (self) / 8.5x (cross) **in the hybrid oracle too** (at 4 bit the attention output
   underflows and the layer returns its quantized bias, so the low delta is capped by the output scale ~0.3).
   For those two the test asserts that the native ratio equals the hybrid's (rel 1e-2). The encoder with
   Linformer (`enc_lin`) separates 28.5x. Consequence (review round 2): at `low` both single-Linformer outputs are
   a constant (1 unique row, std 0; float/high: 336 and 299 unique rows), so their low rows never reach the
   quantized attention graph. These two cases get a 4th mode `mid` (= `low` with datalane f0 = 6; measured in
   the hybrid: f0 = 3 is still constant, f0 = 4 and 6 are input-dependent). The hybrid `mid` output has std
   0.66 / 0.54 against 0.0056 / 0.012 in float, so `mid` is a parity row, not a paired-delta level.
   `test_mid_rows_reach_the_quantized_linformer_graph` asserts both facts (low constant, mid input-dependent).
7. **Golden tolerance 0.** Where the measured max error was exactly 0 (all single-layer `low` cases, both
   Linformer `high` cases), 2x gives a tolerance of 0, i.e. bit-exact. This holds on this CPU. On another
   platform these rows are the first to need re-measuring.
8. **Init-state test (added after mutation M13).** Loading all leaf variables made the golden parity test blind to
   missing HGQ2 config scopes for the Dense-only cases (the bitwidth variables were restored from the file).
   `test_init_quantizer_state_matches_hybrid` compares every non-kernel/bias leaf variable of a freshly built
   native layer with the hybrid's, bit for bit.
9. **Dense initialisation (review round 2).** The weights that parity tests port were never checked at init.
   Hybrid from-scratch starting points: the encoder/decoder Dense layers are built from the config (Keras
   glorot-uniform kernel, zero bias), but the input nets and task heads are torch `Dense` modules ported by
   `kerasify_module` (`src/hepattn/keras/tasks.py:84-93`, `maskformer.py:66-70`), i.e. `nn.Linear`'s
   U(+-1/sqrt(fan_in)) kernel and bias. Native `Dense` now takes `init="keras"` (default) or `init="torch"`
   (VarianceScaling(1/3, fan_in, uniform) kernel + RandomUniform(+-1/sqrt(fan_in)) bias), and `InputNet`
   defaults to `"torch"`. `LayerFactory.dense` passes the initializers through; its defaults are Keras's, so
   the hybrid is unchanged (tests/keras: 104 passed, 8 skipped). Measured on the 27 -> 54 hidden layer:
   native torch-init kernel std 0.110, max 0.1924, bias absmax 0.1920; torch 0.113 / 0.1924 / 0.1921;
   native keras-init 0.156 / 0.2721 / bias 0. S3/S4 task heads must pass `init="torch"` (carried gate).

## Notes for later stages
- S3/S4: task-head `Dense` layers must use `init="torch"` (the hybrid ports them from torch); decoder-layer Dense
  layers keep the Keras default (the hybrid builds them from the config). `test_init.py` shows the checks to copy.

  norm and LayerScale). Plain attention returns `out` (no tuple) unless `value_residual=True`.
- S3/S5: QSoftmax called with `mask=` makes keras attach a mask to its output, and the downstream QEinsum layers emit
  `UserWarning: ... does not support masking` (harmless).
