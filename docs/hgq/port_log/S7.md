## Decisions

1. **Two mappings.** (a) org float: the torch model is instantiated from the saved config (jsonargparse, as
   LightningCLI), the checkpoint is loaded strictly, and each module is ported (`in_proj_weight` / `in_proj_bias`
   split in three by rows, q k v; SwiGLU `Linear(in, 2h)` rows `[:h]` -> `x1`, `[h:]` -> `x2`; `proj_k` / `proj_v`
   rows `[:n]` -> the core's E / F kernel, `[n:]` -> the renorm tail, or dropped where the core has no tail: the
   decoder query self-attention, whose rows past the 16 queries org never reads; LayerNorms only if affine,
   FastLayerNorm has no parameters; register tokens; initial queries; the Fourier `B` buffer). (b) hybrid: its keras
   variables are torch parameters keyed `<module path>._torch_params.<keras variable path>` (keras
   `backend/torch/layer.py` `_track_variables`), the same variable once under every enclosing keras layer (6387 keys,
   1983 distinct variables in the fixture). The native variable with the same leaf-relative path is its twin (shared
   layer names); keras' auto-numbered suffixes (`fixed_point_quantizer_kif_51`) are dropped for the match, and
   variables that then share a path (`QEinsum` `quantizer` / `quantizer_1`) pair in suffix order, the construction
   order on both sides. The 9 plain torch tensors of the hybrid: register tokens, initial queries, `B` (copied), the
   2 `loss_weights` buffers (compared with the native class weights), the 4 `proj_k_dead` / `proj_v_dead` buffers of
   the query self-attention (dropped, as in (a)).
2. **Coverage in both directions** (not only "every native variable written"): every torch tensor read (a tensor of a
   shared module, the tasks under `tasks.*` and `decoder.tasks.*`, counts for all its names) and every native variable
   written; a float source into a quantized target leaves only the HGQ2 quantizer state, `beta` and `ebops` (by
   object: `Quantizer` / `TrainableQuantizerBase` variables, `QLayerBase._beta` / `_ebops`). Measured: org 131 torch
   tensors = 129 read + 2 `loss_weights`, 161 / 161 native variables written; hybrid 1986 / 1986; org float into the
   QAT config 161 written, 1825 kept initial.
3. **`ebops` dtype.** The hybrid stores HGQ2's uint32 `ebops` counter as int64 (torch backend), the native model as
   uint32: an integer-to-integer cast, with values above uint32 saturated and reported (none in the fixture; 176
   casts). Any other dtype or shape difference raises.
4. **Output = S6a checkpoint, model variables only** (`tv`, `ntv`, empty `ov`, step 0, the target's config hash, the
   conversion report as `meta.converted_from`). `main_jax fit --init-from` loads it as a warm start
   (`Trainer.warm_start`: weights, quantizer state and beta; optimizer, step, schedule, beta controller and data
   position fresh); `main_jax test --ckpt` reads it unchanged. The Lightning optimizer state is not converted
   (deviation 1).
5. **Kept export form.** The `kept` leaf is a `QEinsum` of the 1-bit mask with `W[None]`, `W = E[:n]^2 / sum E^2`
   computed from E in the graph; hls4ml refuses the batch-1 operand. The export form is a `QEinsumDense` with the
   frozen `W` (eval mode) as kernel and the leaf's own two input quantizer configs (1-bit mask lane as the input
   quantizer, fixed per-element table lane as the kernel quantizer): the same products of the same quantized values.
6. **Inline silu / sigmoid** (deviation 3). hls4ml 1.3.0 cannot reproduce them: an unknown activation goes through
   `np.ones(k)` with an array `k` (`hls4ml/model/optimizer/passes/bit_exact.py:602`, should be `np.ones_like`): rank 3
   raises `TypeError`, rank 2 followed by a layer fails a shape assert, a rank-2 silu as the last layer writes a call to
   `nnet::silu`, which no template of hls4ml 1.3.0 defines (`grep` of `hls4ml/templates`: no `silu`); sigmoid converts
   but uses hls4ml's own table (C simulation differs, below). The export form replaces the activation by a linear
   copy of the `QDense` + a rank-2 `QUnaryFunctionLUT` of the activation with fixed signed (4, 6) input and (4, 8)
   output lanes: hls4ml-exact, approximate to the trained layer. A bit-exact deployable activation needs the table at
   training time (a model change; FPGA_STATUS "What this means").
7. **No nested models in an export.** A functional model that calls another model as a layer makes hls4ml parse it
   through its da4ml fallback, which aborted the Python process in da4ml 0.6.0 `cmvm` (`Fatal Python error: Aborted`,
   measured on the LUT-form head); `activation_export_layers` returns the layers to apply in sequence.
8. **QSoftmax leaf input lane.** `QSoftmax` has no input quantizer of its own (`enable_iq` False); fed a float input
   directly, hls4ml reads it at its default input precision and C simulation differed in 16856 of 18432 outputs (max
   2.9e-3, falcon, first run). In the model the previous layer's result type sets that precision, so `leaf_model`
   puts a fixed signed (8, 12) quantizer in front of such a leaf; then it is bit-exact.
9. **Mirror, not port, of `tests/keras/test_export.py`.** The hybrid file imports torch and `hepattn.keras` (torch
   backend only), so its 9 tests are mirrored in `tests/keras_native/test_export.py` on native code; the head tests run
   on the org model's classification head (SiLU) instead of the S3 test model's. The inline-silu characterization
   changed form under JAX (decision 6) and pins all three behaviours.

## Deviations from the plan

1. **Warm start, not resume, from a Lightning checkpoint.** The plan's "existing Polaris `.ckpt` files are loaded
   through the S7 converter" is met for the model state. Lightning's optimizer state is indexed by the hybrid's
   parameter-group order, which only an instantiated hybrid (torch backend) can name, and the LR schedule / BetaPID /
   data position of a Lightning run do not map onto the native loop's; the converted checkpoint starts a new run
   (`--init-from`). Warm start keeps the checkpoint's beta; a BetaPID config sets beta at the first epoch start anyway.
2. **The gate "one step" runs 4 steps** (OneCycle needs more than one; all 4 compared).
3. **Inline activations need an export form** (decision 6): hls4ml 1.3.0 cannot convert silu and does not reproduce
   sigmoid. The export form is approximate to the trained layer; the trained graph is exportable bit-exactly only
   with tables at training time (follow-up; FPGA_STATUS).
4. **csim by script on falcon, not by pytest there.** The pytest csim tests need the full `.venv-jax` (torch for the
   converter fixture); `S7_csim.py` builds the same models on macOS, saves them as `.keras`, and the Linux side needs
   only keras, hgq2, jax, hls4ml, da4ml (675 MB venv, removed after the run with its private uv cache).
5. **Edits outside the S7 files**: `tests/keras_native/porting.py` (re-exports the converter's porters),
   `tests/keras_native/test_pr8_layers.py` (expects `ConversionError` instead of `AssertionError` from the porter),
   `.gitignore` (track `s7_fixtures/*/*.npz|json`).
