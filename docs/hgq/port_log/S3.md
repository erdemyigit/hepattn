## Facts measured before or while designing
- Torch semantics kept: classification has `has_first_layer_loss=False` (no layer-0 output); mask runs at every layer;
  incidence and regression run only in `final`. The Residual passes `k`/`v` un-normed (q_sa keys are the raw queries).
  The decoder's `attn_mask` persists into later layers. `use_query_masks` and `mask_queries` are never read by the
  torch forward (they raise here). torch sets `key_valid=None` for batch 1; that is the same math as the all-True mask.
- Hybrid layer-0 paired delta, exact values from the hybrid ledger (`tests/keras/.parity_ledger.jsonl`, same machine):
  high 0.3014124035835266, low 31.091598510742188.
- HGQ2 datalane quantizers default to `overflow_mode="WRAP"` (`SP/hgq/quantizer/config.py:99,136`). In eval mode WRAP
  wraps after rounding (`SP/quantizers/fixed_point/_fixed_point_ops.py`, `FixedPointQuantizer.forward`).
- `torch.topk` on CPU breaks ties differently from JAX `top_k`: on 4-level random data, 2 of 640 columns have a
  different top-2 set (for example torch {44, 81}, JAX {5, 81}).

## Deviations from the plan / hybrid
1. **Task class layout.** The torch task name (`classification`, ...) is `task.task_name`; the keras layer name is
   `task{i}`. Task-head Dense layers default to `init="torch"` (the carried S2 gate, closed below). Decoder FFNs keep
   the Keras init, because the hybrid builds them from the config.
2. **Einsum and softmax leaves in both modes.** The mask and incidence einsum / softmax are factory leaves in float too
   (`EinsumOp` / `SoftmaxOp`); the hybrid's float model uses torch ops there. Same math (float golden rows: 8.6e-6).
3. **The decoder holds the tasks untracked** (`TaskRef`), as torch `decoder.tasks = tasks`; the model owns the
   variables (pinned by `test_decoder_does_not_track_tasks`). Variable paths: `maskformer/task{i}/task{i}_net/...`,
   `maskformer/decoder/initial_queries`, `maskformer/decoder/decoder_l{i}/decoder_l{i}_q_ca/...`,
   `maskformer/decoder/decoder_l{i}/decoder_l{i}_q_ca_res/decoder_l{i}_q_ca_norm/gamma`. S7's converter needs them.
4. **One input type only.** The torch `key_is_<input>` scatter and the `unmerge_inputs` gather are identities; more
   input nets raise. Encoder tasks, pooling, sorting, unified decoding, dynamic queries, kmeans, local strided or flex
   attention, decoder posenc, `use_query_masks`, `mask_queries` and `mtl` raise.
5. **Teacher forcing.** `MaskFormer.call(..., attn_masks={"layer_i": mask})` replaces the computed decoder masks. The
   golden test uses it, so that one threshold flip does not amplify through the mask feedback. It is None in normal use.
6. **Golden storage.** The golden files store no weights. The test rebuilds the torch reference model from its seed
   (and asserts its state sha256), then checks every kernel/bias by sha256 after porting. Only the quantizer state
   (non-kernel/bias leaf variables), the outputs and the hybrid's training-mode loss terms are stored (24 MB -> 7.4 MB).
7. **Regression rows with top-k ties are excluded** from the golden comparison (`regression_tie_rows`). A particle with
   no max-track node takes the top-2 particles per node, and that set is implementation-defined when the 2nd and 3rd
   charged incidences are equal and > 0. The rows are counted, and the count must equal the measured one: 0 in float
   and high (asserted), 48-70 of 300 in low (coarse incidence grid), 0-7 in prod / prodsat.
8. **prod (WRAP) rows are gated only before the first mask feedback.** With the `pflow_hgq.yaml` quantizers (datalane
   i0 = 4, WRAP), native and hybrid differ by 0.207 (torch attention) and 0.026 (Linformer) on the layer-0 mask logits,
   and by up to 62 / 31 on the final mask logits even with the hybrid masks forced. Evidence that the cause is WRAP and
   not the port: the same weights with `overflow_mode="SAT_SYM"` (mode `prodsat`, otherwise identical, pinned by
   `test_chaotic_mode_is_really_wrap`) are bit-exact everywhere for the Linformer model and at layer 0 for the
   torch-attention model. Per layer (scratch S2-style golden files at prod bitwidths), every single Dense, attention
   and Linformer layer is bit-exact under both WRAP and SAT_SYM (innet: 1.2e-7 in both); only the encoders diverge
   (`enc_torch` 3.71 under WRAP vs 6.0e-3 under SAT_SYM; `enc_lin` 2.6e-3 vs 7.2e-7). Under WRAP an ulp-level float
   difference (LayerNorm, residual adds) at a rounding or wrap edge becomes a jump of up to 2**(i+1). So the prod rows
   assert the layer-0 mask logits and layer-0 flips (2x measured) only; the prodsat rows are fully gated.
9. **Quantization losses.** The hybrid's `quant_losses()` counts every task-head layer twice: `keras_layers()` walks
   `model.tasks` and `model.decoder.tasks`, which are the same modules. Measured on the torch-attention model: 111
   layers walked vs 91 unique, 474 vs 391 terms, prod sum 804.9605 vs 804.9105. So the plan's PeriodicEBOPs number
   "804.96" is the double-counted one. `stateless_call(..., return_losses=True)` counts each layer once and equals the
   hybrid's per-layer terms (sorted) bit for bit, except one row (mf_lin/high, rel 9.6e-8). The Keras rule behind this:
   a layer that is called several times keeps the terms of all its calls while it is nested, but a top-level call
   clears its earlier terms. The "final" task loop is top-level, so `stateless_call` counts each task layer once. An
   eager `model(x, training=True)` is one outer call and keeps all of them: `model.losses` has 421 terms vs 411 =
   (2-1) x 4 classification + (3-1) x 3 mask leaves more. S5 must use `stateless_call`, and compare penalties
   against the per-layer sum, not against `quant_losses()`.
10. **Jitted and eager quantized forwards differ** at rounding boundaries (XLA fusion): high-mode layer-0 mask logits
    up to 1.2e-3 apart. So the jitted forward is also checked against the hybrid golden files (`-jit` rows). It is
    not further from the hybrid than the eager one (mf_lin/high layer 0: 3.7e-4 jitted, 4.3e-4 eager).

## Open issues
- G2 needs the Polaris run. The plan's batch-32 comparison is JAX-only, because torch fp32 OOMs at batch 32.
- Golden rows with tolerance 0 (bit-exact on this CPU: the low and prodsat rows and most loss-term rows) must be
  re-measured on the first Linux/GPU run (`golden/measure_mf_golden.py`).
- Hybrid `quant_losses()` double counts the task heads (deviation 9). It is a hybrid bug that also feeds EBOPsMonitor
  and BetaPID in production; the fix belongs to the hybrid, not to this lane. S5: compare against the per-layer sum.
- S5: use the `stateless_call` losses (deviation 9); eager `model.losses` counts repeated task calls.
- S4/S6: top-k ties in the regression proxies (deviation 7) are implementation-defined in torch too (CPU vs CUDA).
- WRAP datalane overflow makes cross-backend quantized parity chaotic at production bitwidths (deviation 8). It may
  also matter for torch CPU vs GPU runs of the hybrid; not investigated.
