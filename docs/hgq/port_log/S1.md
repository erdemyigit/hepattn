## Deviations from the plan
- `keras_native/factory.py` is not byte-identical: `import keras` replaces `from hepattn.keras import keras` (as
  planned), the import sits in the third-party block (ruff isort), and the module docstring says it is
  backend-neutral. The code is otherwise unchanged (`git diff --no-index` shows only these lines).
- `keras_native/__init__.py` does not set or check `KERAS_BACKEND`, because the torch hybrid imports
  `keras_native.factory` through the shim. JAX is selected by the test conftest (later also by the driver).
- `scaling.FeatureScaler.transform` / `inverse_transform` return a new dict; the torch version writes into its
  argument. `VarTransform` raises `ValueError` on an unknown `type` (torch: `assert`) and on an unknown `fn`
  (torch silently applies no fn). Rule: unsupported configs raise.
- `tests/keras_native/__init__.py` exists so test modules import as `tests.keras_native.*`; lanes can reuse
  basenames from `tests/keras` without a pytest module-name clash.

## Review fixes (round 1)

All four review findings were reproduced before fixing.

- **R1 (major) whole-repo pytest broke.** Reproduced: hybrid env, `KERAS_BACKEND` unset,
  `pytest --ignore=tests/experiments/ -m 'not gpu and not requiresdata' --collect-only` gave
  `ERROR tests/keras_native - RuntimeError ... Interrupted: 1 error during collection`, rc=2 (same in `.venv-jax`).
  Fix: `tests/conftest.py` `pytest_ignore_collect` ignores `tests/keras_native` unless keras is (or
  `KERAS_BACKEND` says it will be) jax, and `pytest_terminal_summary` prints `tests/keras_native ignored: ...`.
  After: rc=0, `1029/1042 tests collected (13 deselected)`, 106 `tests/keras/` node ids, 0 native ones
  (same counts as the parent commit). The pixi files are not changed.
  Deviation from the reviewer's sketch: no `config.args` check. pytest loads the conftest of every
  command-line path at startup, before the hook runs, so `pytest tests/keras_native` under torch raises in
  that conftest whatever the hook returns. Measured: with an args check that always returned False (M14),
  all 5 guard tests still passed, so the check had no effect and was removed.
  Consequence: the native suite never runs in the CI unit job (it needs its own process).
- **R2 (major) lazy `import torch` not caught.** Reproduced: `keras_native/zz_lazy.py` with `import torch` in a
  function body; the runtime scan passed (17 of 18 hygiene tests passed, including
  `test_keras_native_imports_no_torch`). Fix: static AST check `test_keras_native_has_no_forbidden_import_statements`
  over every `.py` file, any depth: `import`/`from` (relative ones resolved), `importlib.import_module` and
  `__import__` with a string literal. Forbidden: torch, torchvision, torchaudio, torchmetrics, lightning,
  pytorch_lightning, lion_pytorch, torchjd, and any hepattn module outside `hepattn.keras_native` (stricter than
  the reviewer's list: everything else in hepattn may import torch). The runtime scan stays.
  Consequence for S6/S7: torch-dependent code (ckpt converter, `DataLoader` adapter) lives outside `keras_native`.
- **R3 (minor) env narrower than claimed.** Reproduced: `hepattn.models.wrapper` (lion_pytorch),
  `hepattn.utils.cli` (jsonargparse), `hepattn.utils.visualise_pes` (matplotlib) and
  `hepattn.experiments.clic.lightning_module` failed to import. Fix: installed `lion-pytorch==0.2.3`,
  `torchjd==0.7.0`, `jsonargparse[signatures]==4.40.1`, `matplotlib==3.10.8` (the `hepattn/.venv` versions).
  After: all 41 modules of `hepattn.models`, `hepattn.utils`, plus `lightning_module`, `pflow_data`, import under
  jax, 0 failures. `keras_native_env.txt` regenerated (+16 lines). Transitive pins still differ from
  `hepattn/.venv` in 35 packages (e.g. scipy 1.18.1 vs 1.17.0, as before S1); direct deps match.
- **R4 (minor) recreate recipe unproven.** Verified: `uv venv --python 3.12.0 <scratch>/venv-recreate &&
  uv pip sync --python <scratch>/venv-recreate/bin/python docs/hgq/keras_native_env.txt` (rc=0), then the native
  suite with that interpreter: `65 passed, 14 warnings in 99.45s`. `uv pip sync` is now the documented recreate path.

Lanes: `hepattn-kn-a` and `hepattn-kn-b` were clean at `79778cc` with no own commits, so they were
fast-forwarded (`git merge --ff-only keras-jax`) to inherit R1-R4; the native suite passes in each (65 passed).
