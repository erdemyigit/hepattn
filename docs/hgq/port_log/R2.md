### Design decisions
1. **Static core choice (`linformer_core`).** org decides attend vs project per call (`attn_mask` given or not). The
   keras graph is static and the two paths need different E/F kernels (`bhqn,nk` vs `bhnd,nk`), so the core is fixed at
   build: `"auto"` gives `project` for a self-attention build (`k_shape` None or the same object as `q_shape`, as org's
   `q is k`) and `attend` otherwise. That is right for all four call sites of `linformer.yaml` (encoder self-attention,
   decoder `q_ca`, `q_sa`, `kv_ca`). A call that does not match the core raises `ValueError`.
   `"project_unmasked"` is for decoder `q_sa`: org calls `project(t, E, None)`, which reads only `E[:150]`; the core then
   has no renorm leaves and no tail rows, so the JIT gate needs no exemption. **R3 must pass it** (open issues).
2. **Core leaves are created in `Attention.build`**, inside `factory.scopes()` entered again there: their shapes (q_len,
   kv_len) are known only at build, and HGQ2 reads the scopes at construction. Unused cores are never created, so no
   unbuilt leaf is tracked.
3. **E/F fractional-bit cap.** HGQ2's KBI quantizer trains `b` and `i` separately, so `f = b - i` cannot be constrained.
   E/F kernels (and the tail rows) use a KIF weight quantizer that starts at `min(f0, cap)` (f0 from the active weight
   scope, `b0 - i0` for a KBI spec) with `fc = MinMax(-24, cap)`. Everything else keeps the spec's quantizers.
4. **Renorm lanes are sized for the cap**, not for the initial f_E (plan risk 2): the table-lane and LUT-input
   fractional bits are `2 * cap + 4` = 18 at cap 7, so the table has 2^19 = 524,288 entries (hls4ml limit 1e6; cap 8
   would give 2^21). LUT output: `cap + 3` integer bits (`r <= 2**(cap + 2)` for the smallest nonzero input), `2 * cap`
   fractional bits. These quantizers are non-trainable, so training cannot lower the precision below the bound.
5. **Unknown attention options raise `TypeError`**, the error org's `Attention(**kwargs)` gives for an unexpected keyword.
   With `ValueError`, the R0 xfails marked `raises=TypeError` (R2/R3/R5 files) failed too: 29 failed (one of them the factory-shim test, fixed since) + 3 errors in the
   native suite, against 19 + 3 with `TypeError` (`$S/r2/native_pre.log`, `$S/r2/native_final.log`).

## Deviations from the plan
1. **Paired-delta low end.** The golden `low` and `mid` specs make this attention return a constant (std over the
   queries 0.0, measured; `golden/cases.py` notes the same for Helen's layer), so they never reach the quantized graph.
   The low end is `COARSE_SPEC` (weight b0 6, datalane and table f0 4), which is input-dependent (std 0.188).
2. **High-spec error 2.5e-2, not the prototype's 7e-3.** The cap holds E/F at 7 fractional bits also in the high spec
   (prototype: 18). With the cap lifted (cap 18) the same attention gives 7.9e-3. The convergence sweep lifts the cap
   with the other bits; settings above cap 7 are precision studies, not deployable.
3. **Renorm lanes 18 bits at production, not 16.** The plan's "2 f_E + 4 = 16" uses the initial f_E = 6; E's f can train
   up to the cap, and the plan (risk 2) says to size the LUT for the cap.
4. **E/F quantizer type KIF** although the spec's weights are KBI (design decision 3).
5. **`TypeError`, not `ValueError`, for unknown options** (design decision 5). Plan 5.1's gate "`linformer_proj_dim` and a
   misspelt key raise" holds with either.
6. **Helen-layer tests removed from `test_float_parity.py` and `test_masked_query.py`** (R2 files), so that R5 can delete
   `keras_native/linformer.py` once `golden_utils.py` (R5) and `test_init.py` (R3) stop importing it.
   `port_linformer` stays in `porting.py` for `golden_utils.py`.
7. **Out-projection and value-residual-mix init unchanged** (glorot / keras default): the plan names only q/k/v and E/F.
