## Deviations from the plan

1. **R5-owned test broken by R1.** `tests/keras_native/test_lane_integration.py::test_dummy_targets_give_the_documented_inf`
   asserts that dummy targets give `inf`, which are the pre-`a4263c1` semantics. It passed at R0, so R0 did not mark it, and the
   plan's list of 11 does not include it. R5 owns the file, so I did not edit it. In a scratch copy, this replacement
   passes (dummy 50.488468, real_like 48.844585; 2 passed):

   ```python
   def test_dummy_targets_give_a_finite_loss(batches):
       """Since org a4263c1 (R1), target 1 at padded nodes no longer makes mask_bce inf; real_like still changes
       the loss (the dice target sum and the incidence targets are not masked)."""
       inputs, targets = batches[0]
       model = build_mf("lin", None, inputs)
       dummy, _, _ = matched_loss(model(inputs, training=False), targets, clic_specs())
       real, _, _ = matched_loss(model(inputs, training=False), real_like(targets), clic_specs())
       assert np.isfinite(float(dummy))
       assert np.isfinite(float(real))
       assert float(dummy) != float(real)
   ```

   The `real_like` docstring in that file ("so mask_bce is inf") is also stale.
2. **B1-f added** (2 tests). These tests check exact padding invariance with finite logits at padded nodes. Without them, mutant m03
   (dice without the pad mask) was killed by only 1 test, because `finfo.min` logits make the pad multiply redundant.
3. **B1-d mask_dice tolerance.** Before fix round 1, B1-d checked only that mask_dice was finite. It now compares it with
   torch at `DICE_ATOL` (from B1-a). The measured difference on this fixture is 0, and a tolerance of 0 would pin the float
   rounding of one platform, so the B1-a tolerance for the same function is used.
4. **Matcher and specs tests read both `pflow_hgq.yaml` and org `base.yaml`.** `base.yaml` is the target config. `pflow_hgq.yaml`
   has no owner (R0 open issue) but native must still parse it until R4a or R5 replaces it, so fix round 1 restored its
   matcher row. The specs test has a `base.yaml` row as well; its specs equal `clic_specs()`.
5. **`device_solver` other than `None` raises.** It is not silently ignored. The plan says only "device_solver off".
6. **The plan's B1-a tolerance guess was ~1e-7.** The measured values are 2.38e-7 (bce) and 1.19e-7 (dice), and the tolerances are 2x those.
7. **File ownership: `docs/hgq/port_log/R1_mutants.py`.** Plan section 6 gives `docs/hgq/**` to R5; the rules let a stage add
   only its log `R<n>.md` there. `R1_mutants.py` is a new file next to the log (precedent: R0's `R0_matching_gate.py`), so it
   cannot conflict with R5. The orchestrator must acknowledge it, or move it when R5 merges.
8. **Tests added in fix round 1** (review): B1-g (empty event; the node-count clamp), B1-h (target 1 with finite padded
   logits; the masked dice numerator), the mask_dice parity in B1-d, the `pflow_hgq.yaml` matcher row and a +inf event in
   the sanitising control. Each one kills a reviewer mutant that survived `a37b04a` (m16 to m19, see the mutation table).
