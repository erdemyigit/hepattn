## Findings and deviations from the plan
1. **Torch `mask_bce_loss` / `mask_dice_loss` average across events (kept for parity).** They index the objects
   to `[Nv, N]`, then multiply by `input_pad_mask.unsqueeze(1)` (`[B, 1, N]`), which broadcasts to `[B, Nv, N]`
   (`src/hepattn/models/loss.py:76-88, 211-228`). So each valid object of event q is weighted by the node mask
   of every event b and divided by b's node count, and the mean runs over `B * Nv` terms. Plan 3.3 describes
   the per-event formula; that is not what torch (and so the hybrid) computes when B > 1. Measured (B=2,
   P=4, N=6): torch 0.59988 = cross-event mean 0.59988; per-event mean 0.61045. The port reproduces torch
   with an einsum over a second batch axis (`"qpn,bn->bqp"`). The dice target sum is not masked (torch).
   The PARITY.md `mask_bce = inf` comes from this cross term: an object at a node padded in its own event
   (logit `finfo.min`, target 1 in dummy data, BCE 3.4e38) weighted by another event's pad mask (1).
   Real-like targets (0 at padded nodes) give finite values. **Open question for the user:** this is
   probably an upstream bug; changing it would change the hybrid's training objective too.
2. **NaN targets with l1: the plan's claim is not true in JAX.** `where(mask, |out - nan|, 0)` gives finite
   gradients, because JAX's abs JVP is `select(x >= 0, g, -g)` (`jax/_src/lax/lax.py:4882-4888`, jax 0.11.2),
   not `sign(x) * g`. Measured: `grad(where(False, abs(x - nan), 0))(1.0) = 0.0`, with `square` it is `nan`.
   `nan_to_num` is kept (plan 3.3) because it protects every residual-weighted loss (l2, smooth_l1) and any
   mask-multiply formulation. The control in the test is therefore a residual-squared loss (see gates).
3. **Empty selections give 0, torch gives NaN** (mean of an empty tensor), for `mask_bce`, `mask_dice`,
   `kl_div`, regression `l1`. Tested (`test_no_valid_object_gives_zero_where_torch_gives_nan`).
4. `object_ce_cost` receives class *probabilities* and soft-maxes them again (`task.py:249` passes
   `_class_prob`; `loss.py:54`). Kept for parity.
5. `kl_div_cost` uses `-einsum(log(p + eps), t) / N` instead of torch's `[B, P, T, N]` product + mean
   (same value, max abs diff 4.8e-6 on values ~10, rel 7e-7).
6. The costs keep torch's NaN columns for invalid targets (regression `new_cost` on NaN-padded targets). They
   are under `stop_gradient`, and the host matcher reads only the valid target rows (valid targets first, as
   torch assumes).
7. Only the CLIC configuration is ported. Raises: binary classification (`num_classes=1`), `mask_queries`,
   `query_mask` in targets, any loss/cost name not used by CLIC, regression loss other than `l1`, cost
   mode `old` (also when the torch defaults `smooth_l1` / `old` apply), any other task class. The spec
   dataclasses use the torch defaults (e.g. no class weights, `null_weight=1.0`), not CLIC values.
8. `jax.pure_callback` is called with `vmap_method="sequential"`. A loss function that is traced must close
   over `host_fn`; `match_layers` accepts it for tests (callback counting).

## Open issues
- Finding 1 (cross-event mask losses) needs a user decision; S4 keeps torch semantics.
- `mask_bce` is `inf` whenever padded nodes carry target 1 (dummy data). Real CLIC data should have
  incidence 0 at padded nodes, but this is not checked here; S6 should assert it on real batches.
- Einsum precision on GPU: costs and mask losses use `keras.ops.einsum` in fp32. Whether XLA on the A100
  uses TF32 for these by default is not measured; check `jax_default_matmul_precision` in S5/G3.
- Host matching time is not re-measured here (plan 3.4 numbers stand); `n_jobs` defaults to 1, the
  production config uses 16 (`match_layers(..., n_jobs=16)`).
- Not done in this lane: wiring to lane A's model outputs (S5). The dict layout follows the torch
  `MaskFormer` (`{layer: {task: {key: array}}}`); lane A must emit the same keys.
