## Decisions

1. **Arms.** hybrid-a and hybrid-b differ only in the train order (`data_seed` 42 / 1000042 in the native
   `EpochSampler(seed + epoch)`); same initial weights, config, controller, schedule. jax uses order A; jax-b (order B,
   GPU 3) is a diagnostic outside the verdict. The hybrid gets the native order through its own sampler (a copy of
   `EpochSampler.order`: `native_data` imports jax, which the hybrid env lacks; the test compares both).
2. **Same initial weights.** The hybrid writes a Lightning checkpoint at `on_train_start` (step 0); the converter
   turns it into the native warm start. Hybrid arms load its `state_dict` at `on_fit_start` (fresh optimizer, schedule,
   loops, controller), as `main_jax fit --init-from`.
3. **G4 config.** Production config (`03_make_config.py`, fp32, 1 device) with epochs of 500 steps x 10 = K 5000:
   with the production epoch (7769 steps) and PID warm-up 2 epochs the controller would never act within K.
4. **Verdict** (Erdem's decision 2026-10-24): JAX val loss at K inside mean +- 5.47 |A - B| (90% coverage of an
   exchangeable third run: `(2/pi) atan(c / sqrt(3/4))`, checked by Monte Carlo in the test); the strict [min, max]
   (33% coverage) is reported next to it; `--band` changes c. EBOPs: log10(EBOPs / setpoint) at K inside the same
   band with a 0.01 dex floor, or no farther from the setpoint than the farther hybrid. Preconditions: LR of every
   matched update within 1e-4; the forward check of the converted weights passes in float mode on every platform
   (section "Forward check"; the 0.05 x max |logit| quantized check of `f6930a6` was replaced on 2026-10-25).
5. **Hybrid checkpoint steps never on an epoch's last step** (default every 96; JAX every 200). Measured: a resume
   from a checkpoint written on the last batch of an epoch skips that epoch's validation and the next epoch's
   `on_train_epoch_start` in Lightning 2.5.2 (`FitLoop.reset`, restart stage still set): beta stayed at init_beta after
   the resume (tiny run, kill at step 4 = epoch end, ckpt every 2). `check_ckpt_steps` refuses such intervals.
6. **Train set: full** (`--num-train -1`). Measured RSS of `CLICDataset` on the local `train_clic_fix.root`: 0.427 GB at
   20k and 1.366 GB at 80k events, 15.65 kB per event -> ~15.6 GB per process for the full set; pickle 6.6 kB per
   event. Worst case per node: 4 arms x (1 process + 4 workers) x 15.6 GB = 313 GB < 512 GiB per Polaris node (ALCF
   user guide, `docs/polaris/index.md`). `--num-train` gives a subset.

## Bug fixed: hybrid BetaPID lost its state on every resume

`hepattn.keras.callbacks.BetaPID` had no `state_dict`, so Lightning saved nothing for it: a resumed run re-seeded the
controller and its next step returned init_beta. This affects every resumed hybrid run (also `05_sweep.pbs` on the
preemptable queue). Test `test_controller_state_survives_a_checkpoint` fails without the fix
(`assert after == betas[3:]`); mutants m20 / m21 below.

## The step-1 train-loss residual (0.2-0.4%)

At step 1 (accumulation 2) JAX - hybrid was +0.095 on 24.8 (order A). With the LR set to 1e-30 and accumulation 1, the
loss of each batch at the converted init weights ([G4_evidence/step1_residual.txt](G4_evidence/step1_residual.txt)):
4 of 8 batches agree to <= 1.2e-6 relative, the others differ by 1.2e-4 to 3.8e-3. Batch 1 (the last micro-batch of
step 1) is the 0.38%: hybrid 24.82736, native 24.92240, the same numbers as the step-1 rows. Of its +0.0950, the final
regression L1 is +0.0825 (87%), mask BCE +0.0075, object CE +0.0034. Ruled out: data order (first batches compared
input by input: equal sums of every input), weights (converted bit for bit, class logits equal), LR (6.3e-7), matcher
solver (both `scipy.optimize.linear_sum_assignment`), what is logged (both: task loss of the step's last micro-batch).
Consistent with the documented S3 deviation 7: the regression proxy takes the top-2 particles per node, and with
quantized (tied) incidence values the set is implementation-defined (`torch.topk` vs JAX `top_k`, S3.md "tie"). Not
proven per row here. On Polaris the report's `early_agreement` shows the size at production scale.

## Forward check (2026-10-25): the Polaris init's failure is platform arithmetic, not the conversion

Polaris init `g4a` (job 7782770) failed the quantized forward check (final mask logits 174.5 at scale 175.8,
13k-51k attention-mask flips per layer, layer-0 class logits exactly equal). The question: torch-GPU vs XLA arithmetic
amplified by quantization, or a conversion error the small S7 fixture missed. Measured on the Mac CPU at production
size (`init --accelerator cpu --num-train 2000`, real `val_clic_fix.root` events, 32 events, highest matmul precision,
evidence in [G4_evidence/forward_bisect/](G4_evidence/forward_bisect/) and
[G4_evidence/forward_check_production_cpu.json](G4_evidence/forward_check_production_cpu.json)):

| Comparison (final mask logits unless stated) | max abs | median abs | other |
|---|---|---|---|
| hybrid vs native, quantized, both CPU | 183.6 (scale 124.9) | 1.53 | layer-0 mask flips 17679 / 768000 |
| hybrid vs hybrid with every float input +1 ulp, quantized | 235.1 (scale 124.9) | 1.58 | layer-0 mask flips 18968 / 768000 |
| native vs native +1 ulp, quantized | 183.3 (scale 184.8) | 1.57 | layer-0 mask flips 19925 / 768000 |
| hybrid vs native, float mode (every HGQ2 `Quantizer` the identity) | 4.3e-5 (scale 18.9) | 4.5e-6 | worst output 2.3e-6 of its scale, 0 flips in every layer |
| hybrid vs hybrid +1 ulp, float mode | 3.9e-5 | 4.8e-6 | worst 2.9e-6, 0 flips |
| standalone hybrid forward vs the init stage's Lightning forward (CPU) | 0 | 0 | 22 / 22 outputs bitwise |

Verdict: **(1), arithmetic amplified by quantization; the conversion is correct.** CPU against CPU shows the same
size of difference as Polaris (GPU kernels are not needed to explain it), and the quantized model moves by the same
amount when its own inputs move by one ulp. Layer by layer (every keras layer call recorded on both sides, matched by
layer name, `forward_bisect/`): every layer before encoder layer 0's q/k/v input quantizers agrees within 6e-7; there
the input quantizers of q, k and v each round 6 of 1,376,256 values differently, all at a half-LSB tie (x * 256 =
202.499985 vs 202.5, 224.500000 vs 224.499969, ...). No layer whose inputs agree produces different outputs anywhere
else. The divergence becomes large at encoder layer 1's softmax inverse-table input lane: its sums reach 42.1, the
lane holds +-16 and WRAPs, so a 0.73 difference in a sum becomes a full-range jump in 1.3% of the rows; from there it
grows through the network. Float mode removes rounding, WRAP and tables and leaves the converted weights: they agree
to 2.3e-6, the same as one ulp. Checked: the batch has no event with every node valid (24-112 of 160 valid nodes), so
org's `key_valid=None` case does not arise in it.

Change (`polaris/19_g4_compare.py`, `19_g4_hybrid.py forward`): the forward check is now a matrix on the init batch,
per platform (GPU and CPU on Polaris, CPU locally): hybrid (standalone, quantized / float / quantized +1 ulp) and
native (quantized / float). **Gate: float mode, hybrid vs native, every output within 1e-4 of its scale and at most
1e-4 of the mask entries flipped, on every platform** (`FLOAT_RTOL`, `FLIP_FRAC`; measured 2.3e-6 and 0). Reported:
the quantized comparison next to the hybrid's own 1-ulp spread, hybrid GPU vs CPU and native GPU vs CPU (both
modes), and the Lightning init forward vs the standalone forward. `forward-check` (PBS `G4_STAGE=forward`) re-runs it on
an existing init and updates its manifest; `run` refuses to train an init whose check does not pass
(`--ignore-forward` overrides). Controls of the gate at production size (`native-forward --control`): the encoder
layer-0 q kernel transposed: outputs off by 100% of their scale, 20730 layer-0 mask flips; one decoder layer-3 kernel
x 1.01: worst output 1.1e-2 of its scale (112x the tolerance), 0 flips. Both fail the gate; the unperturbed weights
pass it with a 44x margin.

What float mode does not check: the quantizer state (bitwidths). The converter copies it and checks the coverage both
ways (S7: every variable bit for bit at fixture size); a bitwidth mismatch would show only in the quantized outputs,
which the 1-ulp chaos hides at the init weights. Model note (not a G4 issue): the WRAP overflow of the softmax
inverse-table input lane at the init weights (sums to 42 in a +-16 lane) changes 1.3% of the encoder layer-1 softmax
rows completely; whether training widens the lane is open.
